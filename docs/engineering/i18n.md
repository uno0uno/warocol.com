# UI i18n (shell foundation)

Batch **#1602** / epic **#1598**. Spanish is the product default. English covers **app shell only**.

## Stack

- `@nuxtjs/i18n` (Nuxt 3)
- `defaultLocale` / `fallbackLocale`: `es`
- Locales: `es`, `en` only
- `strategy: no_prefix` — routes stay `/pos`, `/ventas`, etc. (no `en/` URL prefix)
- Message files: `i18n/locales/es/shell.json`, `i18n/locales/en/shell.json`

## Locale resolution

1. Cookie `waro_locale` (`es` | `en`) — user override, survives reload  
2. `businessProfile.locale` when B1 (#1599) exposes it  
3. Fallback `es`

Use `useAppLocale()` (`composables/useAppLocale.ts`) for switches and sync.

## What is translated today

Shell chrome only:

- Auth login + auth layout chrome  
- Dashboard nav labels, sidebar logout, mobile bottom nav / settings language toggle  
- Dashboard shell header CTAs  
- Shared `TheErrorState`  
- Dashboard layout breadcrumb root + subscription fallbacks  

**Not** translated: POS, ventas, inventory, module pages, marketing/blog bulk, legal.

## How modules opt in later

1. Add keys under `i18n/locales/es/*.json` and `i18n/locales/en/*.json` (new domain files ok; register in `nuxt.config` `i18n.locales[].files` if split).  
2. Replace user-visible strings with `t('domain.key')` / `$t` **only in that module’s PR**.  
3. Missing English keys fall back to Spanish — never leave blank UI.  
4. Do **not** mass-migrate modules in drive-by PRs.

## Manual smoke

1. Cold load with no cookie → Spanish shell matches production copy.  
2. Language toggle: **desktop** account/tenant modal or **mobile** Settings → Language → English → nav/auth/header shell strings switch; module body stays Spanish.  
3. Reload with `waro_locale=en` → first HTML should already be English (SSR plugin, not client-only).  
4. Clear cookie → back to `es` (or tenant locale when B1 is live).  
5. Logout clears `localStorage` but **not** the `waro_locale` cookie.
