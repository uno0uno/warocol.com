# UI i18n (module kit)

Epic **#1607** / batch **#1608**. Spanish is the product default. English covers the **app shell** plus a shared **module kit** (`common` keys, locale-aware dates). Operator modules (POS, ventas, …) still opt in per batch PR.

## Stack

- `@nuxtjs/i18n` (Nuxt 3 / v9)
- `defaultLocale` / `fallbackLocale`: `es`
- Production locales: `es`, `en`, `pt`, `fr`, `de`, `hi`, `zh`, `ar`
- `strategy: no_prefix` — routes stay `/pos`, `/ventas`, etc. (no `en/` URL prefix)
- Message files (lazy, multi-file):
  - `i18n/locales/{locale}/shell.json` — nav, shell chrome, auth, errors
  - `i18n/locales/{locale}/common.json` — shared actions + empty-date labels
  - `i18n/locales/{locale}/pos.json` — POS cart/checkout chrome (#1609)
  - `i18n/locales/{locale}/operaciones.json` — operaciones sub-nav + ops hotspots (#1609)
  - `i18n/locales/{locale}/cocina.json` — KDS + comandas monitor (#1609)
  - `i18n/locales/{locale}/ventas.json` — ventas list/detail/create chrome (#1610)
  - `i18n/locales/{locale}/facturacion.json` — facturación UI chrome only (#1610; not FE/Matias payloads)
  - `i18n/locales/{locale}/abastecimiento.json` — inventario/abastecimiento primary chrome + warehouse glossary (#1611)
  - `i18n/locales/{locale}/menu.json` — menú list/filter chrome (#1611)
  - `i18n/locales/{locale}/finanzas.json` — finanzas primary chrome (#1612)
  - `i18n/locales/{locale}/analitica.json` — analítica primary chrome (#1612)
  - `i18n/locales/{locale}/equipo.json` — equipo/salarios/nómina chrome (#1612)
- Registered in `nuxt.config` `i18n.locales[].files` (not single `file`)
- Operator warehouse glossary: `useWarehouseCopy()` → `abastecimiento.glossary.*`; static `WAREHOUSE_COPY` remains ES fallback for guest/out-of-i18n surfaces

## Locale resolution

1. `tenant_public_profiles.ui_locale` after the active tenant loads — authoritative for every user in the tenant
2. Cookie `waro_locale` before tenant hydration — SSR cache only, synchronized from the tenant
3. Fallback `es`

The separate backend `locale` remains limited to `es|en` for receipts and emails.

Use `useAppLocale()` (`composables/useAppLocale.ts`) in components for switches and `t()`.
Do **not** call `useI18n()` / `useAppLocale()` from Nuxt plugins — use `nuxtApp.$i18n` instead (`plugins/i18n-locale.ts`).

## Formatters (dates / numbers)

- `composables/useFormatters.ts` follows **active UI locale** (`useI18n().locale`).
- Tags come from `utils/appLocales.ts`: `es-CO`, `en-US`, `pt-BR`, `fr-FR`, `de-DE`, `hi-IN`, `zh-CN`, and `ar-u-nu-latn` for the first Arabic POS rollout.
- Tenant **timezone** remains from `useTenantTimezone` (calendar day must not break).
- Empty date labels: `t('common.notSpecified')` / `t('common.nA')`.

## How modules opt in

1. Add the domain file under every enabled `i18n/locales/<locale>/<domain>.json` directory.
2. Register the filename in `LOCALE_MESSAGE_FILES`; Nuxt derives every locale path from the catalog.
3. Replace user-visible strings with `t('domain.key')` / `$t` **only in that module’s PR**.
4. Prefer `common.*` for shared actions (Save, Cancel, Loading…) instead of redefining them.
5. Missing locale keys fall back to Spanish — never leave blank UI.
6. Do **not** mass-migrate unrelated modules in drive-by PRs.

Key naming: `domain.section.key` (mirror shell: `nav.*`, `auth.*`, `common.*`). ES copy stays 1:1 with previous hardcoded Spanish when migrating.

Special characters in message strings (`@`, `{`, `}`, `|`) must be escaped for vue-i18n message syntax — e.g. email placeholders use `tu{'@'}correo.com`, not `tu@correo.com`.

## Manual smoke

1. Cold load with no cookie → Spanish shell matches production copy.
2. Change the tenant language in Operaciones > Personalizar and verify every tenant user receives it.
3. Reload with a synchronized `waro_locale` cookie → first HTML should use the tenant language (SSR plugin, not client-only).
4. Dates/relative times follow the selected locale; timezone still follows the tenant.
5. Verify long German text, Hindi glyph height, Chinese segmentation, and Arabic RTL with Latin POS digits.
6. Clear the cookie → SSR starts in Spanish, then synchronizes from the loaded tenant.
7. Logout clears `localStorage` but **not** the `waro_locale` cookie.

## Adding and releasing a locale

1. Add the locale metadata to `utils/appLocales.ts` with `enabled: false`.
2. Generate candidate catalogs with `npm run i18n:translate -- <code>`.
3. Run `npm run i18n:check:all`; all 13 files, keys, variables, and Vue I18n messages must match Spanish. `i18n:check` validates production-enabled locales only.
4. Have a native reviewer approve every domain and record the approval in `i18n/review-status.json`.
5. Set the locale metadata to `enabled: true`, then repeat `i18n:check`, unit tests, Nuxt build, and manual smoke.

The six 2026-07 locales were enabled through an explicit product activation decision; native linguistic QA remains a follow-up. Do not expand the separate backend receipt/email locale beyond `es|en` until gettext catalogs and its database constraint are included in another rollout.

Arabic sets `<html dir="rtl">`; operational numeric formatting deliberately uses Latin digits through `ar-u-nu-latn`. OCR and DIAN formatting remain Colombia-specific and do not follow the UI locale.
