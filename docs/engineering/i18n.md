# UI i18n (module kit)

Epic **#1607** / batch **#1608**. Spanish is the product default. English covers the **app shell** plus a shared **module kit** (`common` keys, locale-aware dates). Operator modules (POS, ventas, …) still opt in per batch PR.

## Stack

- `@nuxtjs/i18n` (Nuxt 3 / v9)
- `defaultLocale` / `fallbackLocale`: `es`
- Locales: `es`, `en` only
- `strategy: no_prefix` — routes stay `/pos`, `/ventas`, etc. (no `en/` URL prefix)
- Message files (lazy, multi-file):
  - `i18n/locales/{es,en}/shell.json` — nav, shell chrome, auth, errors
  - `i18n/locales/{es,en}/common.json` — shared actions + empty-date labels
- Registered in `nuxt.config` `i18n.locales[].files` (not single `file`)

## Locale resolution

1. Cookie `waro_locale` (`es` | `en`) — user override, survives reload
2. `businessProfile.locale` when present
3. Fallback `es`

Use `useAppLocale()` (`composables/useAppLocale.ts`) in components for switches and `t()`.
Do **not** call `useI18n()` / `useAppLocale()` from Nuxt plugins — use `nuxtApp.$i18n` instead (`plugins/i18n-locale.ts`).

## Formatters (dates / numbers)

- `composables/useFormatters.ts` follows **active UI locale** (`useI18n().locale`).
- Tags: `es` → `es-CO`, `en` → `en-US` via `toNumberLocaleTag` (`utils/parseLocaleDecimal.ts`).
- Tenant **timezone** remains from `useTenantTimezone` (calendar day must not break).
- Empty date labels: `t('common.notSpecified')` / `t('common.nA')`.

## What is translated today

- Auth login + accept-invitation / verify / customer-verify chrome
- Dashboard nav labels, sidebar logout, mobile bottom nav / settings language toggle
- Dashboard shell header CTAs
- Shared `TheErrorState`
- Shared `common.*` action labels (seed for modules; wire as you touch UI)
- Date/relative formatting via UI locale

**Not** translated yet (later epic batches): POS, ventas, inventory, finanzas module pages, marketing/blog bulk, legal.

## How modules opt in

1. Add a domain file under `i18n/locales/es/<domain>.json` and `en/<domain>.json` (e.g. `pos.json`).
2. Register both paths in `nuxt.config` `i18n.locales[].files` for es and en.
3. Replace user-visible strings with `t('domain.key')` / `$t` **only in that module’s PR**.
4. Prefer `common.*` for shared actions (Save, Cancel, Loading…) instead of redefining them.
5. Missing English keys fall back to Spanish — never leave blank UI.
6. Do **not** mass-migrate unrelated modules in drive-by PRs.

Key naming: `domain.section.key` (mirror shell: `nav.*`, `auth.*`, `common.*`). ES copy stays 1:1 with previous hardcoded Spanish when migrating.

Special characters in message strings (`@`, `{`, `}`, `|`) must be escaped for vue-i18n message syntax — e.g. email placeholders use `tu{'@'}correo.com`, not `tu@correo.com`.

## Manual smoke

1. Cold load with no cookie → Spanish shell matches production copy.
2. Language toggle: **desktop** account/tenant modal or **mobile** Settings → Language → English → nav/auth/header + wired common/date strings switch; module body still Spanish until its batch.
3. Reload with `waro_locale=en` → first HTML should already be English (SSR plugin, not client-only).
4. Dates/relative times format with en-US when locale=en; timezone still tenant.
5. Auth leftovers (`/auth/accept-invitation`, `/auth/verify`, `/auth/customer-verify`) show EN chrome when locale=en.
6. Clear cookie → back to `es` (or tenant locale when set).
7. Logout clears `localStorage` but **not** the `waro_locale` cookie.
