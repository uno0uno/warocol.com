# 运营活动日志

**活动日志** 是 POS 的审计记录：谁在哪个渠道（餐桌、吧台或柜台）做了什么、何时以及（如适用）原因。店主、管理员和主管用它审查商品删除、标签页或购物车清空以及部分付款作废。

## 如何访问

侧边栏 → **运营 → 活动日志**。

您将看到分页的事件列表。顶部可按日期、渠道、操作类型筛选，并按商品名称搜索。点击行查看技术事件详情（便于支持）。

> **权限：** 仅拥有 **运营** 模块访问权限的用户可打开活动日志（通常为店主、管理员和主管）。无此模块的收银人员看不到该标签页，也无法查看历史。

## 活动日志记录的内容（POS）

每行是团队使用 POS 且功能已在您的商家启用后自动生成的 event。

| 活动日志中的操作 | 含义 |
|------------------|------|
| **商品已添加到标签** | 向餐桌或吧台标签添加了项目 |
| **商品已从标签移除** | 从标签（餐桌/吧台）移除了项目 |
| **数量已修改** | 更改了标签中项目的数量 |
| **标签已清空** | 清空了餐桌或吧台会话的标签 |
| **购物车行已移除** | 从柜台或吧台购物车移除了商品 |
| **购物车已清空** | 清空了整个购物车 |
| **支付已作废** | 作废了结账时已记录的部分付款 |

每个事件还包括：

- **时间** — 日期和时间
- **用户** — 在系统中执行操作的人
- **渠道** — 餐桌、吧台或柜台
- **摘要** — 商品和数量，或作废付款详情
- **餐桌** — 适用时的餐桌名称
- **原因** — POS 中捕获的文本（见下方政策）
- **订单** — 存在时的销售链接

## 不记录的内容

| 情况 | 为何不出现 |
|------|------------|
| **发送到标签之前**购物车中的商品，或购物车与服务器同步之前 | 仅审计到达服务器的操作 |
| 商家部署活动日志**之前**的操作 | 记录从生产环境启用开始，不回填过去 |
| 从销售 → 订单作废**整笔销售** | 另一流程；不同于结账时作废部分付款 |
| 价格、折扣或菜单配置更改 | 超出 POS MVP 范围 |

刚启用后列表为空是正常的：团队使用包含活动日志的版本开始操作后会出现事件。

## 如何筛选

| 筛选 | 用途 |
|------|------|
| **日期范围** | 限定时段（日历含今天、上周等快捷方式） |
| **渠道** | 仅餐桌、仅吧台、仅柜台或全部 |
| **操作** | 特定类型（如仅「支付已作废」或「商品已从标签移除」） |
| **搜索商品** | 在摘要上自由文本（payload 中的商品名） |

使用 **清除** 移除所有筛选。更改筛选或使用面板标题刷新按钮会更新列表。

## 原因政策

### 商品已发送到厨房（餐桌或吧台）

若 **厨房工单** 已启用且商品**已进厨房**（不再为「新建」状态），从标签移除需**强制填写原因**后方可确认。该文本保存在活动日志 **原因** 列，厨房在 KDS 上仍看到作废行。

若商品**尚未发送到厨房**，可无原因移除。

### 作废部分付款

在 **结账** 时移除已记录的付款（部分付款上的删除图标），可填写可选原因。留空则系统在活动日志中记录 **「无原因」**。

> 若为**现金**付款，POS 会在确认前提醒将现金 physically 退还给顾客。见 POS 指南中的 [部分付款](../pos#cobro-parcial-split)。

## 事件详情

点击任意行（移动端为卡片）打开详情。可查看完整**原因**、**订单**链接（如有）及技术格式 **payload**（JSON）— 便于支持调查。

## 常见问题 — 活动日志

**活动日志能替代监控或收银对账吗？**
不能。它是 POS 敏感操作的记录，不是视频或收银关闭。

**收银员能看到经理填写的原因吗？**
仅当其角色有 **运营** 访问权限。多数收银员看不到活动日志。

**能导出到 Excel 吗？**
MVP 中屏幕无导出；请用筛选和分页按时段查看。

**为何昨天没有事件，我们已在用 WARO？**
记录从商家获得包含活动日志的版本开始，不重建此前历史。

**柜台购物车移除商品总会记录吗？**
会，当购物车已与服务器同步。仅在本地、系统保存前的更改不产生事件。
